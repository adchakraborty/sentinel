01 / How It Works

From One Prompt to a Full Security & QA Report

You give NEMESIS a URL, your product docs, and login credentials. It reads everything, logs in like a real user, explores the app, designs tests, runs them, and delivers a report — all automatically.

STEP 1

You Provide the Basics

Point NEMESIS at your app: the URL, your product documentation, login credentials, and sample data (e.g. a search term or a test user name). That's all you need.

STEP 2

NEMESIS Reads & Explores

It reads your docs to understand the app. Then it opens a real browser, logs in (even through enterprise SSO), and crawls every page — mapping forms, buttons, menus, and routes.

STEP 3

AI Designs the Tests

Using what it learned from your docs and the crawl, the AI creates a tailored test plan: security attacks, functional checks, input validation, and edge-case exploration — specific to your app.

STEP 4

Tests Run in a Real Browser

Every test executes in a real Chromium browser — clicking buttons, filling forms, trying malicious inputs — just like a human tester would. Screenshots are captured as evidence.

STEP 5

Report & Remember

You get a clear report with every finding, severity, and screenshot proof. NEMESIS remembers what worked — the next scan starts smarter.

What Happens at Each Step

Step 1

You Say What to Test

In plain English, you tell NEMESIS: "Here's my app URL, here's the documentation, here are the login credentials, and here's some example data." One prompt. No configuration files, no setup wizards, no scripting.

Step 2

It Understands Your App

NEMESIS reads your product documentation to learn what the app does — its pages, features, user flows, and business rules. Then it opens a real browser, logs in (handling SSO, multi-factor, and consent screens), and maps every page, form, and button it finds.

Step 3

AI Creates a Custom Test Plan

Unlike traditional scanners that run the same generic checks on every app, NEMESIS builds a test plan specific to your application. It knows your routes, your forms, your data model — so it tests what matters. Security attacks, functional smoke tests, input validation, and edge cases are all generated fresh.

Step 4

Real Browser, Real Testing

Tests run in a real Chromium browser — not a proxy or a packet sniffer. NEMESIS clicks buttons, fills out forms, submits data, navigates between pages, and tries malicious inputs. Every action is captured with a screenshot so you can see exactly what happened.

Step 5

Clear Reports, Growing Intelligence

Results come back as a prioritized list: critical issues at the top, passing checks at the bottom. Reports are available in HTML, Markdown, and formats that plug into your CI/CD pipeline. Every successful finding is saved — the next time you scan, NEMESIS already knows what worked and starts from a smarter baseline.

The Key Difference

No Hardcoded Patterns

Traditional security scanners ship with a static database of thousands of known attack patterns and run them all blindly. NEMESIS ships with zero. The AI generates every test, every payload, and every detection rule on the fly — tailored to the specific app it's testing. This means it can find issues that cookie-cutter scanners miss.

Think of It This Way

Traditional scanners are like a locksmith who tries the same 10,000 keys on every door. Most don't fit. It's slow, noisy, and misses custom locks.

NEMESIS is like hiring a security expert who reads the building blueprints first, understands how each door works, and then picks only the right tools for each lock. Faster, smarter, and more thorough.

03 / What It Tests

Four Types of Testing, One Tool

Most tools do one thing. NEMESIS replaces your security scanner, your QA tester, your input validation suite, and your exploratory tester — all in a single run.

Security Testing

Can a Hacker Break In?

NEMESIS tries to hack your app the way a real attacker would: SQL injection, cross-site scripting, bypassing login, accessing files it shouldn't, and more. Every attempt is documented with screenshot evidence.

Functional Testing

Does the App Actually Work?

Does search return the right results? Does login work with valid credentials? Do dialogs open and display the correct fields? NEMESIS tests your app's features like a QA engineer would.

Input Validation

What Happens With Bad Input?

Special characters, extremely long text, empty fields, foreign language characters. NEMESIS tests every input field to make sure your app handles unexpected data gracefully instead of crashing or leaking information.

Exploratory Testing

What Did Nobody Think to Test?

NEMESIS explores like a curious user: trying invalid URLs, clicking things in unexpected order, entering boundary values. It finds the edge cases that scripted tests miss because nobody thought to write a test for them.

Enterprise Login Support

Works With Your SSO

NEMESIS handles enterprise single sign-on automatically: it clicks the login button, gets redirected to your identity provider, fills in credentials, handles consent screens, and waits for the redirect back. Works with Hyland, Okta, Azure AD, and more.

Pipeline-Ready Reports

Results You Can Act On

Get results as a visual HTML report, a Markdown summary, or in SARIF format that plugs directly into GitHub's Security tab. Run NEMESIS in your CI/CD pipeline and see findings as alerts alongside your code.
