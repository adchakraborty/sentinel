From One Prompt to a Full Security & QA Report

You give SENTINEL a URL, your product docs, and login credentials. It reads everything, logs in like a real user, explores the app, designs tests, runs them, and delivers a report — all automatically.

Point SENTINEL at your app: the URL, your product documentation, login credentials, and sample data (e.g. a search term or a test user name). That's all you need.

First, SENTINEL generates baseline attacks from recon data — SQLi, XSS, CORS, IDOR, SSRF, traversal, and more on every input and API endpoint it found. Then the AI adds app-specific attacks tailored to your routes, tech stack, and business logic.

What Happens at Each Step

Step 1

You Say What to Test

In plain English, you tell SENTINEL: "Here's my app URL, here's the documentation, here are the login credentials, and here's some example data." One prompt. No configuration files, no setup wizards, no scripting.

Step 2

It Understands Your App

SENTINEL reads your product documentation to learn what the app does — its pages, features, user flows, and business rules. Then it opens a real browser, logs in (handling SSO, multi-factor, and consent screens), and maps every page, form, and button it finds.

Step 3

Baseline + AI Test Plans

SENTINEL uses a two-layer approach. First, it generates baseline attacks directly from recon data — deterministic SQLi, XSS, CORS, IDOR, SSRF, traversal, auth bypass, CSRF, accessibility, and UX checks on every input and API endpoint discovered. Then the AI adds app-specific attacks tailored to your routes, tech stack, and business logic. Baseline ensures consistent coverage; AI adds depth.

Step 4

Real Browser, Real Testing

Tests run in a real Chromium browser — not a proxy or a packet sniffer. SENTINEL clicks buttons, fills out forms, submits data, navigates between pages, and tries malicious inputs. Every action is captured with a screenshot so you can see exactly what happened.

Step 5

Clear Reports, Growing Intelligence

Results come back as a prioritized list: critical issues at the top, passing checks at the bottom. Reports are available in HTML, Markdown, and formats that plug into your CI/CD pipeline. Every successful finding is saved — the next time you scan, SENTINEL already knows what worked and starts from a smarter baseline.

The Key Difference

Two Layers: Baseline + AI

Traditional scanners ship with a static database of thousands of generic attack patterns and run them all blindly. SENTINEL takes a smarter approach: baseline attacks are generated deterministically from your app's actual recon data (every input, every API endpoint, every form), ensuring consistent coverage. Then the AI layer adds bespoke attacks tailored to your specific tech stack and business logic — finding issues that neither generic scanners nor static baselines would catch.

Step 6 is the key. In Rapid7/AppScan, steps 1–5 feed a static rule engine. In SENTINEL, recon data first generates baseline attacks — deterministic SQLi, XSS, CORS, IDOR, SSRF, traversal, and more on every discovered input and API endpoint. Then the GitHub Models API (GPT-4o) reasons about what else to test — adding app-specific attacks the baseline can't generate. The AI knows this app uses CSRF tokens, so it tests CSRF bypass. It read that /folder/:folderId is a route, so it tests IDOR. Baseline ensures consistency; AI adds intelligence.

Think of It This Way

Traditional scanners are like a locksmith who tries the same 10,000 keys on every door. Most don't fit. It's slow, noisy, and misses custom locks.

SENTINEL is like hiring a security team: one expert systematically checks every door and window (baseline), while another reads the building blueprints and picks specialized tools for the custom locks (AI). Together, they're faster, smarter, and more thorough — and they never miss the basics.

Where AI Is Leveraged

SENTINEL uses a two-layer approach: baseline attacks from recon data ensure consistent coverage, while the AI layer adds app-specific intelligence. Here's how each layer contributes:

Baseline

Deterministic Attacks from Recon

The baseline engine generates attacks directly from crawl data: SQLi and XSS on every text input, CORS probes, IDOR on API endpoints, SSRF on preview/proxy URLs, path traversal, auth bypass, CSRF on forms, accessibility audits, and UX checks. These run every scan, ensuring consistent results.

AI decides

Reads & Understands Documentation

The LLM reads your product docs (markdown, text) and extracts routes, features, business rules, tech stack, and user flows. This understanding shapes the app-specific tests it generates.

AI decides

Generates App-Specific Attacks

Beyond the baseline, the LLM generates bespoke attacks tailored to your specific app — custom payloads for your tech stack, business logic tests, and edge cases that a deterministic engine can't anticipate.

AI decides

Sets Success Indicators

The LLM decides what constitutes a "finding" for each AI-generated test. The baseline uses heuristic detection — pattern matching for SQL errors, XSS reflection, sensitive data exposure, and file content signatures.

AI decides

Prioritizes & Triages Results

The LLM assigns severity (critical/high/medium/low) based on real-world impact, not a generic formula. It explains findings in context of your specific application.

Tool executes

Browser Automation & Evidence

Playwright drives a real Chromium browser: navigating pages, filling forms, clicking buttons, capturing screenshots. Both baseline and AI attacks execute in the same real browser — faithfully and with evidence.

04 / What It Tests

Six Types of Testing, One Tool

Most tools do one thing. SENTINEL replaces your security scanner, your QA tester, your input validation suite, your accessibility auditor, your UX checker, and your exploratory tester — all in a single run.

Security Testing

Can a Hacker Break In?

SENTINEL tries to hack your app the way a real attacker would: SQL injection, cross-site scripting, bypassing login, accessing files it shouldn't, and more. Every attempt is documented with screenshot evidence.

Functional Testing

Does the App Actually Work?

Does search return the right results? Does login work with valid credentials? Do dialogs open and display the correct fields? SENTINEL tests your app's features like a QA engineer would.

Input Validation

What Happens With Bad Input?

Special characters, extremely long text, empty fields, foreign language characters. SENTINEL tests every input field to make sure your app handles unexpected data gracefully instead of crashing or leaking information.

Exploratory Testing

What Did Nobody Think to Test?

SENTINEL explores like a curious user: trying invalid URLs, clicking things in unexpected order, entering boundary values. It finds the edge cases that scripted tests miss because nobody thought to write a test for them.

Enterprise Login Support

Works With Your SSO

SENTINEL handles enterprise single sign-on automatically: it clicks the login button, gets redirected to your identity provider, fills in credentials, handles consent screens, and waits for the redirect back. Works with Hyland, Okta, Azure AD, and more.

API Security

Tests Your APIs Too

SENTINEL doesn't just test web pages — it probes your JSON APIs for SSRF, IDOR, mass assignment, information disclosure, and insecure direct object references. It reads your API docs and generates targeted API-specific attacks.

Pipeline-Ready Reports

Results You Can Act On

Get results as a visual HTML report, a Markdown summary, or in SARIF format that plugs directly into GitHub's Security tab. Every finding includes CWE references and remediation recommendations.

Accessibility

WCAG Compliance Checks

SENTINEL audits your app for accessibility violations: missing alt text, unlabeled form inputs, broken heading hierarchy, missing skip-to-content links, and missing lang attributes. Catches issues that block screen readers and keyboard users.

UX Testing

Usability & Quality Checks

Broken images, dead links, slow page loads, unlabeled inputs, and content overflow. SENTINEL checks the user experience basics that manual QA often misses, ensuring your app works well for real users.

Web Dashboard

Beautiful Real-Time UI

Run SENTINEL from your browser — enter a URL, watch the scan in real-time with live progress, and get an interactive results dashboard with severity cards, risk gauge, category breakdown, and downloadable reports. This is the primary way to use SENTINEL.

07 / How Sentinel Is Different

SENTINEL vs. Traditional DAST

Tools like Rapid7 InsightAppSec, HCL AppScan, Burp Suite, and OWASP ZAP are established DAST scanners. They work by firing thousands of pre-built payloads at every input and matching responses against known vulnerability signatures. SENTINEL takes a fundamentally different approach.

The Core Difference: AI Reasoning vs. Signature Matching

Rapid7 / AppScan / Burp / ZAP ship with a database of thousands of known attack signatures. They crawl your app, fire every payload at every input, and check if the response matches a known vulnerability fingerprint. They don't understand your app — they just pattern-match.

SENTINEL uses a two-layer approach. Baseline attacks are generated deterministically from your app's actual recon data — every input, every API endpoint, every form gets tested with targeted payloads. Then the AI layer (GPT-4o) reads your documentation, studies the recon, and designs bespoke attack plans for your specific business logic. Baseline ensures consistency; AI adds intelligence.
