01 / How It Works

LLM-in-the-Loop Architecture

The LLM doesn't just trigger scans. It reads docs, plans tests, executes attacks, and learns from results. Every test is generated, not hardcoded.

STEP 1

nemesis_scan

One call: URL + doc path + auth creds + example data. Reads docs, authenticates (form, IDP/OIDC, cookie, bearer, basic), crawls.

STEP 2 — THE LLM

LLM Plans

Combines docs + recon + example data + past payloads to generate security attacks, QA tests, input validation, and exploratory tests.

STEP 3

nemesis_attack

Executes all test plans in a real Chromium browser. Captures screenshots and evidence for every finding.

STEP 4

Reports

Markdown, HTML, JSON, SARIF reports. Evidence screenshots. All in ./nemesis-results/.

STEP 5

Learn & Grow

Effective payloads saved per URL. Next scan starts smarter. Knowledge persists across sessions.

03 / Features

Security + QA + Validation + Exploration

Not just a security scanner. A complete AI testing platform that handles everything from SQLi to form validation to functional smoke tests.

Security

Penetration Testing

SQL injection, XSS, auth bypass, path traversal, CORS, CSRF, CRLF injection. All in a real browser with screenshot evidence.

QA Testing

Functional Verification

Does search work? Does login accept valid creds? Do Create Document/Folder/Task dialogs load? The LLM tests functionality like a QA engineer.

Validation

Input Sanitization

Special characters, null bytes, unicode, extremely long strings, double-encoded payloads. Tests every input surface for proper sanitization.

Exploratory

Edge Case Discovery

Random inputs, boundary values, deeply nested routes, invalid IDs. The LLM explores like a curious tester finding what nobody thought to test.

Enterprise Auth

IDP / OIDC Login

Built-in support for enterprise IDP flows: click login button → redirect to external IDP → fill credentials → handle consent → redirect back. Works with Hyland, Okta, Azure AD.

CI/CD

SARIF + Reports

Markdown, HTML, JSON, and SARIF output. Integrates with GitHub Security tab. Run in CI, see results as alerts.

Authentication Types

form-login

Auto-fills username/password on a login form and submits

idp-login

Clicks app login button, fills IDP credentials, handles OAuth consent, waits for redirect

cookie

Sets session cookies directly in the browser context

bearer

Adds Authorization: Bearer header to all requests

basic

HTTP Basic Authentication with username/password
